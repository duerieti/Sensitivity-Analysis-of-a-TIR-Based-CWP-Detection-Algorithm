\section{Operationalisation of Surrounding Stream temperature}

% The later was achieved by rethinking the operationalsiation of the idea of surrounding stream temperature as given by the ecological definition. Instead of relying on the mean temperature of fixed slabs, the new algorithm deploys a inverse distance weighting scheme to compute a reference temperature for each cell by deploying a inverse distance weighting scheme. This guarantees that the reference temperature for pixel flagging is always a mutliperspective decission taking surrounding temerature values of different locations into account to provide a surrounding temperature. This strategy as the added benefit that the deployed reference temperature is a spatially continuous phenomenon unlike the older purely slab based approach. Therefore sharp cutoffs of cwps at slab boundaries can no longer occur unlike in the old algorithm

\section{Implementation Detail}

% generally the implementation to a large degree follows the implementation of the time optimized cwp algorithm only differing from said function in the computation of the reference temperature step.

% the following pseudo code provides a detailed overiev of this new reference temperature computation

% 1. From a uniform distribution with bounds 500-3000 meters, sample 20 values as
%    candidate step lengths.
% 2. For each of the 20 step length values:
%    - divide the river reach into n centerline segments based on the step
%      length.
%    - construct a 3-pixel-wide narrow reference strip polygon for each
%      segment.
%    - extract the median temperature of each segment from the (unrounded)
%      TIR raster using the reference strip polygon.
%    - get the "visual center" of each strip polygon as a point and assign
%      the corresponding reference temperature to this point.
% 3. Pool the reference points (location + temperature) from all 20 step
%    length values into a single combined set of IDW sample points.
% 4. Initiate a new raster which will be populated by reference temperature
%    values.
% 5. For each cell in this new raster:
%    5.1 if the cell at the same location in the TIR raster has a NaN value,
%      set the pixel to NaN and continue to the next cell.
%    - else, compute a weighted temperature value for this pixel using
%      inverse distance weighting over the pooled reference points.
% 6. Round the TIR raster using a fixed rounding factor.
% 7. Subtract the rounded TIR raster from the reference raster; flag pixels
%    where the difference exceeds delta T, producing a binary CWP raster.
% 8. Polygonize the binary CWP raster into patch polygons.
% 9. Filter patches by minimum area, compute per-patch temperature
%    statistics, and apply a patch-level threshold check against the
%    reference temperature.


% Step 4. is thereby written in C++ and imported into R using the package Rcpp. This, as it was identified as a computationally intensive step which is best implemented in an compiled language. To further increase the execution speed of this step, parallelisation on the thread level was deployed, as the inverse distance computation for very pixel is an embarisingly parlallel computation. For the parallelisation stepup, the OpenMP library was deployed.



\section{Reduction of parameters}

% as mentioned, the buffer px parameter was fixed. Due to the distributed reference points and the inverse distance weighting, no zone slab length is needed anymore. Additionally, since the extent of the reference raster is allways mached to the extend of nodata pixels in the TIR raster due to 5.1, a slab half width also does not have to be set. This however also means, that the algorithm can only be applied to exact water masks of rivers and the shore needs to be cut out. The remaining parameters are the paths to the raster and the centerline, the minimal patch area, the rounding factor, the temperature delta, wheter diagonal pixels should be counted as neighbours in rasterisation. Additionally a new parameter was introduced, which lets a user set the number of cores used for internal parallelisation.

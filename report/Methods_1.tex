\subsection{Reimplementation of the CWP algorithm based on GDAL and system calls}


The current algorithm focuses on per slab processing of the raster using a set of R loops and relying on terra and sf functions to implement the logic. The reworked algorithm is disk/file based and deployes GDAL over its command line interface directly. This decission was choosen, as terra operations are are somethimes not to performant and GDAL offers a often faster set of geocomputational tools which can be called from R using system() or sf::gdal\_utils() \citep{lovelace2019geocomputation}. Further, empirical testing in a prior coursework exercise also showed a significant speedup of GDAL-based raster operations compared to \texttt{terra} across a range of use cases \citep{duerr_raster_deepdive}. This coursework was not peer-reviewed and is cited here only as a supporting empirical observation. Additionally the GDAL approach was also choosen, as it enables easy chunk processing with reading and writing to disk, which helps to keep memory foodprint small. This can be beneficiial in a HPC setting, where not only the number of available cores but also the available memory can be comme an issue in performing computations. The draw back of this decission is that writing intermediate results to disk causes large spikes in disk space consumption, as intermediate reasters of the algorithm can be up to 25 GB large. This was counteracted by deploying compression during writing and decompression during reading, a strategy that only produced little computational overhead but greatly reduces the size of the intermediate results. Speciffically, this can be implemented by setting the compression options \texttt{COMPRESS=DEFLATE} and \texttt{PREDICTOR=2} when working with GDALs geotiff driver \citep{gdal_gtiff_driver}. Lastly it should also be pointed out that heavily relying on gdal introduces a lot of I/O activity, which can significantly hurt performance on distributed file systems. To further optimize execution speed, \texttt{terra::extract()} was replaced with \texttt{exact\_extract()} from the \texttt{exactextractr} package. This was done as \texttt{exact\_extract()} extracts aggregated values from rasters considerably faster than \texttt{terra::extract()} for large rasters \citep{mieno_rgis_2022}; it should be noted, however, that this speed difference was not tested in isolation within this work. A further difference between the two functions concerns how partially covered cells are handled: \texttt{exact\_extract()} performs a coverage-fraction-weighted extraction, in which partially covered cells are weighted by their fraction of coverage \citep{isciences_exactextract}, whereas \texttt{terra::extract()} by default includes a cell only if its center point falls within the polygon \citep{hijmans_terra_extract} -- the behaviour used in the original (v1) implementation. To approximate this cell-center-inclusion behaviour within \texttt{exact\_extract()}, only cells with a coverage fraction of at least 50\% were included. This approximation is not exactly equivalent to terra's center-point rule.

\section{Sensitivity Analysis using Morris}

With the algorithm optimized, sensitivity analysis can now be carried out to determine the sensitivity of the CWP detection algorithm with respect to the parameters buffer pixel count, step length and temperature delta. Especially of interest is to observe the difference in sensitivity towards the step length parameter between tributary-caused and non tributary-caused CWP. For this reason a pre selection method is deployed to guarantee that the studied CWP are sensitive towards the step length parameter. Senistivity towards pixel buffer count and temperature delta are also of interest. (Tonolla et all.) allready found in their sensitivity analysis, that the buffer pixel count seems to have little influence on the CWP area. If this finding can be replicated algorithmic simplifcation using factor fixing (refference to theory) might be possible. Additionally, the temperature delta parameter is among the most influential according to Tonolla et. all. It is of generally interest a tool to determine the validity of the method, to check wheter the same is found. The general approach can be logically segmented into two steps, section 1 focues on determining CWP that are succeptible to the step length parameter and classifying these cwp into tributary-caused and non tributary-caused CWP. The second step focuses on deriving morris sensitivity indices for these CWP with respect to their area.

\subsubsection{Creation of a fuzzy overlay of CWP}

the resulting cwp polygon layers where then processed into an singular raster over a series of processing steps. Firs each polygon layer was rasterized using the same pixle size as the TIR rasters. Then these different raster representations of the cwp where staked into a multy layer raster and a pixel whise mean calculation was performed. This aggregates the threee dimensional raster stack into a two dimensional raster. The pixel whise mean computation produces a pixel score between 0 and 1 which can be interpreted the following way. A pixel value of 1 indicates that this area of the emme basement, was part of a cwp during each of the runs. A pixel value near zero indicates that the area covered by the pixel almost never was part of a cwp in the model outputs. The resultign raster can be understood as a fuzzy membership representation of the CWPs in the emme where each pixel has a probability score of belonging to a cwp. From these fuzzy cwps it can also be read which cwps are variable with respect to the step lengt (or the buffer pix => which hoverwer has a neglectable influence as seen in the results). \subsubsection{Selection and Classificatio of CWP}


From this fuzzy cwp raster, cwp pixels which where clearly variable and which mode of creation could clearly be attributed to tribuaries or not tribuatries where then selected and classified into groups tributary-caused and non tributary-caused. The selection and classificaiton process was not carried out algorithmically due to time constraints but was based on a visual interpretation of the patches. First patches where judeges based on their coloring as beeing variable or non variable. For this patches where generally determined as variable, when their colloring held a significant amount of grey and black pixels. These cwp then undervent classification. For a cwp to be tributary caused, the closenes to a tributary inflow aswell the shape of the cwp where taken into account. Cwp clarling originating in their shape from a tributary inflow and beeing close to the inflwo where determined as tributary caused. To detect the tributaries open streat map aswell as the swiss image where deployed. The open streat map faccilicated the possibility to spot tributaries which might be obscured by forest or buildings on the swiss images, while the swissimage provided the oportunity to spot tribuaries which might not be mapped on open streat map as open streat map is based on volunteered geographic content and therefore can not be assumed as beeing complete. A total of 24 cwp patches which are variable and can be clearly attributed to beeing tributary caused or non tributary caused where selected and classified. \subsubsection{Computing specially lumped statistics for the selected CWPs}

In the next step the extracted bounding boxes locating the area of the selected cwp aswell as the results from this larger morris experiment are brought together. For each bounding box, the CWP/CWPS lying inside this bounding box are extracted out. Next the total area covered by CWP in the bounding box is computed and the area weighted mean temperature delta of all CWPS ins the bounding box are computed. If there is only a singular CWP in the bounding box, then this just corresponds to the temperature delta of this singular CWP. If a bounding box is completely empty for a run with a specific parameter combination, which happens when for this specific run no CWP at all was computed at this location, then the total area is set to zero m2 and the temperature delta is set to zero degrees celsius. The later is a trivial approach, where no CWP is of course eqivalent to a CWP with zero surface area. The second one makes sense in the sence that a CWP with no temperature difference to its surrounding per definition can not be a CWP and therefore does not exist. So a temperaure delta of zero for a non exsiting CWP makes logical sense.

The area and temperature delta measure is then finaly paired with the morris index of the parameter tuple and the identifier of the bounding box. This way the measures can be linked back to the parameter combination that produced them and the location of the bounding box. Also the determined class of the cwp is added to this too. Figure \ref{fig:second_execution_run} is providing a graphical overview of this process using a CWP created though the Limpbach inflow into the emme near Utzenstorf BE.

\subsubsection{Computing morris sensitivity indices}


Lastly, the morris sensitivity indices mu.star, mu and sigma are computed with respect to the total CWP areas for each bounding box.

To later on make the calculated morris indices comparable to each other normalisation of the patch area was needed. This since without normalisation, large patches would dominate smaller patches just due to their size. So for every location/bounding box Min max scaling into the zero one range was performed. where the largest area value ever produced for this bounding box over all computational runs corresponds to 1 and zero corresponds to the case when the bounding box is completely empty in a specific run. 

Computation of the morris indices was then performed with respect to these total area measures by again utilising the sensitivity package. As introduced in the theoretical background does morris produce one ensitivity index (mu, mu.star or sigma). for each parameter that was varied in the experiment. So for every location/ bounding box recorded two sensitivity values (mu.star and sigma) are produced for every parameter. So a total fo 6 parameters.

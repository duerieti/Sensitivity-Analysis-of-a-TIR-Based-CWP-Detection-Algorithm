\subsection{Reimplementation of the CWP algorithm based on GDAL and system calls}



% the current algorithm focuses on per slab processing of the raster using a set of R loops and relying on terra and sf functions to implement the logic. The reworked algorithm is disk/file based and deployes GDAL over its command line interface directly. This decission was choosen, as terra operations are are somethimes not to performant and GDAL offers a often faster set of geocomputational tools which can be called from R using system() or sf::gdal_utils()  https://r.geocompx.org/geometry-operations.  Further, empirical testing also shows, that in a range of usecases, GDAL offers a significent speedup in computation compared to terra. This was allready tested in a coursework (gh pages link). Genreally GDAL is written in C++ and provided a battle tested and optimized api to perform geocomputations, therefore an effort was taken to express as much of the cwp algorithm as possible in GDAL. Additionally the GDAL approach was also choosen, as it enables easy chunk processing with reading and writing to disk, which helps to keep memory foodprint small. This can be beneficiial in a HPC setting, where not only the number of available cores but also the available memory can be comme an issue in performing computations. The draw back of this decission is that writing intermediate results to disk causes large spikes in disk space consumption, as intermediate reasters of the algorithm can be up to 25 GB large. This was counteracted by deploying compression during writing and decompression during reading, a strategy that only produced little computational overhead but greatly reduced the size of the intermediate results. < here the thenical is important. Which compression is deployed, which flag>. Lastly it should also be pointed out that heavily relying on gdal introduces a lot of I/O activity, which can significantly hurt performance on distributed file systems.

\section{Sensitivity Analysis using Morris}

Figure xy provides a high level overwiev of the methodology deployed to answer the research questions. The mehtod can be split up into two sequential segments, where segment 1 is setting the stage for segment 2. First, the morris parameters are sampled to then perform a sensitivity analysis by only varying the buffer width and the step length. The resulting parameter tuples are then deployed in model evaluation, each tuple beeing used to create one set of CWP. The resulting CWP are then used to create fuzzy representations, which allow for the visual determination which CWP are subject to change between parameter tupples. CWP that are subject to change and can be clearly be attributed to either beeing tributary cause or not tributary caused, their bounding box is then extracted. Next, another morris sampling is set up creating parameter tuples for buffer width, step length also the temperature difference. The model was again executed on these parameter touples. Then from each set of resulting cwp the bounding boxes are used to extract the cold water patches which where previously determined to vary due to either the step length or the buffer pixels used. For each of the selected patches, the total area is then computed. The total patch area is then used to perform the sensitivity analysis using the morris method.

\subsubsection{Creation of a fuzzy overlay of CWP}

% the resulting cwp polygon layers where then processed into an singular raster over a series of processing steps. Firs each polygon layer was rasterized using the same pixle size as the TIR rasters. Then these different raster representations of the cwp where staked into a multy layer raster and a pixel whise mean calculation was performed. This aggregates the threee dimensional raster stack into a two dimensional raster. The pixel whise mean computation produces a pixel score between 0 and 1 which can be interpreted the following way. A pixel value of 1 indicates that this area of the emme basement, was part of a cwp during each of the runs. A pixel value near zero indicates that the area covered by the pixel almost never was part of a cwp in the model outputs. The resultign raster can be understood as a fuzzy membership representation of the CWPs in the emme where each pixel has a probability score of belonging to a cwp. From these fuzzy cwps it can also be read which cwps are variable with respect to the step lengt (or the buffer pix => which hoverwer has a neglectable influence as seen in the results). CPWs which show a lot of differnt shades in their colourling, hold pixels which are generally variable in their identiy as cwp pixel or non cwp pixel. \subsubsection{Selection of CWP}


% From this fuzzy cwp raster, cwp pixels which where clearly variable and which mode of creation could clearly be attributed to tribuaries or not tribuatries where then selected and classified into groups tributary-caused and non tributary-caused. The selection and classificaiton process was not carried out algorithmically due to time constraints but was based on a visual interpretation of the patches. First patches where judeges based on their coloring as beeing variable or non variable. Cwp clarling originating in their shape from a tributary inflow and beeing close to the inflwo where determined as tributary caused. To detect the tributaries open streat map aswell as the swiss image where deployed. The open streat map faccilicated the possibility to spot tributaries which might be obscured by forest or buildings on the swiss images, while the swissimage provided the oportunity to spot tribuaries which might not be mapped on open streat map as open streat map is based on volunteered geographic content and therefore can not be assumed as beeing complete.
